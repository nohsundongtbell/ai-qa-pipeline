# 테스트 계획서 — 게시판 웹앱

| 항목 | 내용 |
|---|---|
| 대상 시스템 | 게시판 웹앱 (Node.js + Express + SQLite, 순수 HTML/CSS/JS) |
| 테스트베이시스 | [docs/requirements.md](requirements.md) (REQ-001 ~ REQ-014) |
| 관련 문서 | [docs/test-cases.md](test-cases.md) (TC, 추적성 매트릭스) |
| 작성 방식 | AI가 초안 작성, QA가 리뷰 후 보강 (리뷰 결과는 test-cases.md 하단 "리뷰 메모" 참고) |

## 1. 목적

- 요구사항 14개가 구현되어 있는지 검증한다.
- 요구사항에 없지만 위험한 동작(보안, 경계값, 예외 입력)을 찾아 결함 또는 요구사항 보강 항목으로 올린다.
- 이후 단계에서 자동화(Playwright), CI 실행, 품질 게이트(Go/No-Go)의 기준이 되는 TC 세트를 만든다.

## 2. 테스트 범위

### 2.1 포함 범위

| 영역 | 내용 | 관련 REQ |
|---|---|---|
| 회원가입 | 정상, 중복, 입력 검증(경계값), 비밀번호 해시 저장 | REQ-001, 002, 003, 013 |
| 로그인/로그아웃 | 정상/실패, 세션 유지와 종료, 로그인 상태 조회 | REQ-004, 005 |
| 게시글 목록 | 표시 항목, 정렬, 페이지네이션, 잘못된 파라미터 | REQ-006, 007 |
| 게시글 작성 | 정상, 권한, 입력 검증, XSS | REQ-008, 012, 013 |
| 게시글 상세 | 조회, 존재하지 않는 글, 버튼 노출 조건 | REQ-009 |
| 게시글 수정/삭제 | 본인만 가능(403), 비로그인(401), 없는 글(404) | REQ-010, 011, 012 |
| REST API 공통 | 응답 형식, 상태 코드, 존재하지 않는 경로 | REQ-014 |
| UI 화면 | 5개 화면의 주요 흐름과 오류 메시지 표시 | 전체 |

### 2.2 제외 범위 (이번 라운드에서 하지 않음)

| 제외 항목 | 사유 |
|---|---|
| 성능/부하 테스트 | 실습용 단일 프로세스 앱, 요구사항에 성능 기준 없음 |
| 다중 브라우저, 모바일 호환성 | Chromium 1종만 대상. 요구사항에 명시 없음 |
| 접근성 정식 감사(WCAG) | label, role 속성만 확인. 정식 감사는 제외 |
| 서버 재시작 후 세션 유지 | 세션 저장소가 메모리 방식임을 알려진 제약으로 수용 |
| 이메일, 비밀번호 찾기, 프로필 수정, 댓글, 검색 | 구현되지 않은 기능 |
| 인프라, 배포 환경 테스트 | 배포 파이프라인은 4단계 이후 범위 |

## 3. 테스트 접근 방식

| 레벨 | 방법 | 도구 (예정) |
|---|---|---|
| API 테스트 | HTTP 요청으로 상태 코드, 응답 본문, 권한 검증 | Playwright `request` 컨텍스트 |
| UI 테스트 | 브라우저에서 사용자 흐름과 화면 메시지 검증 | Playwright (getByRole, getByLabel 우선) |
| DB 검증 | 비밀번호 해시 저장 여부 등 DB 직접 확인 | better-sqlite3 (읽기 전용) |
| 탐색적 테스트 | 요구사항 밖의 보안, 예외 입력 확인 | 수동 |

적용 기법: 동등 분할, 경계값 분석(아이디 4/20자, 비밀번호 8자, 닉네임 2/20자, 제목 1/100자, 페이지 10개), 상태 전이(비로그인 ↔ 로그인 ↔ 로그아웃), 권한 매트릭스(비로그인 / 작성자 / 타인).

### 3.1 권한 매트릭스 (핵심 검증 대상)

| 동작 | 비로그인 | 작성자 본인 | 타인 |
|---|---|---|---|
| 목록/상세 조회 | 허용 | 허용 | 허용 |
| 작성 | 401 | 허용 | 허용 |
| 수정 | 401 | 허용 | **403** |
| 삭제 | 401 | 허용 | **403** |

## 4. 테스트 환경과 데이터

- 서버: `PORT`, `DB_PATH` 환경변수로 테스트 전용 포트와 DB를 사용한다. 운영용 `board.db`는 건드리지 않는다.
- 브라우저: Chromium (Playwright 기본)
- 테스트 데이터:
  - 사용자 U1(작성자), U2(타인)을 사전조건에서 API로 만든다.
  - 아이디는 실행마다 고유값(예: `u1_` + 타임스탬프)을 써서 서로 영향을 주지 않게 한다.
  - 페이지네이션 TC는 API로 글을 대량 생성해 준비한다.
- 격리 원칙: TC는 서로 의존하지 않는다. 각 TC가 필요한 데이터를 직접 만든다.

## 5. 우선순위 정의

| 등급 | 기준 | 예시 |
|---|---|---|
| P1 | 핵심 기능, 보안, 권한. 실패하면 배포 불가 | 로그인, 작성, 본인만 수정/삭제(403), XSS |
| P2 | 주요 검증, 경계값, 대표 오류 흐름 | 입력 길이 경계, 페이지네이션 |
| P3 | 부가 동작, 표시 세부 사항 | 줄바꿈 표시, 재삭제 시 404 |

실행 순서는 P1 → P2 → P3입니다. CI의 빠른 검증(스모크)은 P1만 실행합니다.

## 6. 자동화 전략

- 자동화 대상(Y): 결과가 결정적이고 반복 가치가 큰 TC. 전체의 대부분을 자동화한다.
- 수동 유지(N): 서버 재시작이 필요하거나, 요구사항이 불명확해 판정 기준이 없는 탐색적 항목.
- 구성: API 테스트를 먼저 자동화(빠르고 안정적)하고, UI 테스트는 핵심 흐름 위주로 자동화한다.
- 각 테스트 이름에 TC ID를 넣어 결과와 요구사항을 추적한다. (예: `TC-076 타인 글 수정 시 403`)

## 7. 진입/종료 기준

**진입 기준**
- 앱이 `npm start`로 정상 기동된다.
- 요구사항 문서와 TC가 리뷰를 마쳤다.

**종료 기준 (Go/No-Go 후보)** — 실제 판정 기준은 [quality-gate.json](../quality-gate.json)이며, CI의 `metrics` job이 매 main push마다 평가합니다. 기준을 바꾸면 이 표도 함께 갱신하세요.

| 항목 | 기준 |
|---|---|
| P1 TC 통과율 | 100% |
| 전체 TC 통과율 | 95% 이상 |
| Critical/Major 결함 | 0건 (미해결) |
| 요구사항 커버리지 | REQ 14개 모두 TC 1건 이상 |
| Flaky rate | 5% 이하 (재시도 후 통과 비율) |

## 8. 리스크와 대응

| ID | 리스크 | 영향 | 가능성 | 대응 |
|---|---|---|---|---|
| R-01 | 타인 글 수정/삭제 권한 검증 누락 | 높음 | 낮음 | 권한 매트릭스 전 조합을 API와 UI로 검증 (P1) |
| R-02 | 게시글 제목, 내용을 통한 XSS | 높음 | 중간 | 스크립트 태그 입력 후 실행 여부 확인 (P1) |
| R-03 | 세션 관리 취약점 (로그인 실패 횟수 제한 없음 → 무차별 대입, CSRF는 SameSite 쿠키에만 의존) | 높음 | 중간 | 탐색적 테스트 항목(EX-06, EX-07)으로 등록하고 결과를 결함 후보로 보고. 세션 고정은 로그인 전 세션이 없어 위험 낮음(확인함) |
| R-04 | 과도하게 큰 요청 본문이 500 에러로 처리됨 (TC-065, **수정 완료**: 413 반환) | 중간 | 낮음 | 자동화 후 회귀 검증 |
| R-05 | 요구사항이 불명확한 항목 (아이디 대소문자, 닉네임 중복, 비밀번호 최대 길이) | 중간 | 높음 | 기획 확인 후 요구사항에 반영. 결정 전에는 판정하지 않음 |
| R-06 | UI 테스트 불안정 (로딩 타이밍, `confirm` 창) | 중간 | 중간 | 자동 대기 사용, 다이얼로그 핸들러 명시, 데이터 격리 |
| R-07 | 세션이 메모리 저장이라 서버 재시작 시 로그인 소실 | 낮음 | 높음 | 알려진 제약으로 수용, 제외 범위에 명시 |
| R-08 | 테스트 데이터가 누적되어 목록 TC가 흔들림 | 중간 | 높음 | 테스트마다 별도 DB 파일, 실행 전 초기화 |

## 10. 결함 심각도

| 등급 | 기준 |
|---|---|
| Critical | 데이터 유출, 권한 우회, 서비스 중단 |
| Major | 핵심 기능 동작 불가, 잘못된 상태 코드로 요구사항 위반 |
| Minor | 부가 기능 오류, 메시지/표시 문제 |
| Trivial | 오탈자, 스타일 |
